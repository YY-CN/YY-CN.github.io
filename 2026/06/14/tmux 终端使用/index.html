tmux 终端使用

在 云服务器上跑实验时，最崩溃的莫过于本地网络突然闪断，导致跑了一半的脚本直接被终止。tmux (Terminal Multiplexer) 就是为了解决这个问题而生的。它可以让你的任务在后台持续运行，随时随地重新连接查看进度。

核心概念：为什么需要 tmux？

当你通过 SSH 或 Jupyter 终端连接到服务器时，你启动的进程是依附于当前终端会话的。终端一关，进程就死。
tmux 可以在服务器端创建一个持久化的虚拟终端。即使你的电脑关机、断网，tmux 里的实验依然在服务器上稳稳地跑着。

⌨️ 进阶快捷键：多窗口与滚动查看日志

在 tmux 中，所有的快捷键操作都需要先按一个**前缀键 (Prefix)**，默认是 **Ctrl + b**。

1. 查看历史输出（极其重要！）

在 tmux 里，默认情况下你无法直接用鼠标滚轮向上翻看历史运行日志。

  1. 进入滚动模式：按 Ctrl + b，松开后按 [
  2. 现在你可以用键盘的上下方向键，或者 Page Up / Page Down 来自由翻看历史输出了。
  3. 退出滚动模式：按 q 或 Esc。

2. 屏幕分屏 (Panes)

想在一块屏幕上边看 GPU 占用率（watch -n 1 nvidia-smi），边看代码日志输出？

  • 左右分屏：Ctrl + b，松开后按 %
  • 上下分屏：Ctrl + b，松开后按 "
  • 在分屏间切换光标：Ctrl + b，松开后按方向键 ↑ ↓ ← →
  • 关闭当前光标所在的分屏：直接输入 exit 或按 Ctrl + d

error connecting to /tmp/tmux-0/default (No such file or directory)

的原因非常简单：

因为你当前根本没有在 tmux 会话（Session）里面。

tmux source-file 命令的作用是让当前正在运行的 tmux 实例重新加载配置文件。如果你直接在普通的终端（比如 AutoDL 的标准 JupyterLab 终端或普通 SSH 窗口）里运行它，它找不到正在运行的 tmux 服务，就会报这个错。

不过别担心，你的配置文件其实已经成功写入了！

如果还没进入 tmux，也没关系，下一次打开 tmux 会自动生效。

📋复制与粘贴的终极奥义

在 tmux 中复制粘贴有两个完全不同的场景，最核心的秘诀在于 Shift 键。

场景一：把服务器里的代码/报错，复制到你自己的电脑上（最常用）

痛点：开启了 mouse on 之后，你会发现直接用鼠标选中文本，一旦松手选择就消失了，根本没法 Ctrl+C 复制到本地。
解决方案：按住 Shift 键！

  1. 复制：按住键盘上的 Shift 键不放，然后用鼠标去选中文本。此时系统会绕过 tmux 的拦截，调用你本地终端的原始选中功能。选中后，直接使用本地的复制快捷键（Win: Ctrl+Insert 或 右键复制，Mac: Cmd+C）。
  2. 粘贴：想把本地代码粘贴到 tmux 里，同样按住 Shift 键，然后点击鼠标右键进行粘贴（或者 Shift+Insert / Cmd+V）。

场景二：在 tmux 的不同分屏内部互相复制粘贴 (纯键盘流)

如果你只是想把左边分屏的一段路径，复制到右边分屏，不需要经过本地电脑的剪贴板，可以使用 tmux 内置的复制模式：

  1. 进入复制模式：按 Ctrl + b，松开后按 [ （右上角会出现行号指示器）。
  2. 移动光标：用方向键移动到你要复制的开头位置。
  3. 开始选择：按下 **空格键 (Space)**，然后用方向键移动光标，选中你需要的文本（文本会高亮）。
  4. 确认复制：按下 **回车键 (Enter)**。高亮消失，文本已经保存在 tmux 的内部剪贴板了，同时自动退出了复制模式。
  5. 粘贴：切换到你想粘贴的地方，按 Ctrl + b，松开后按 **]**，内容就粘贴出来了。

总结：开启 set -g mouse on 获得滚轮自由，配合 Shift 键实现本地与服务器的无缝复制粘贴，这两个技巧能解决 tmux 90% 的使用痛点。
